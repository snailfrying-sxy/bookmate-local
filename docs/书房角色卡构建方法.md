# 书房角色卡构建方法

## 目的

书房角色卡不是让泊舟模仿作者、人物或一位虚构的人类。它是一张由读者维护的、只在当前书房生效的交流视角卡：当读者回到一本书时，泊舟知道应该把注意力放在哪里、怎样推进，以及不该把什么简化掉。

它借鉴 [book-to-skill](https://github.com/virgiliojr94/book-to-skill) 的关键方法：**提取结构，而不是把整本书或一段摘要重复塞进上下文**。但输出从开发代理的 Skill 改成了服务于读者对话的角色卡。

## 角色卡结构

| 组成 | 对应的结构化问题 | 在书房中的作用 |
| --- | --- | --- |
| 角色名 | 这间书房希望保留什么样的思考姿态？ | 为交流视角命名，便于读者辨认与调整。 |
| 主要关注 | 哪些主题、矛盾或关系值得反复回来？ | 相当于核心框架或心智模型。 |
| 工作原则 | 回应时必须遵守哪些判断规则？ | 约束回应的次序与精度。 |
| 推进方式 | 可以怎样从材料走向更深的问题？ | 相当于可执行的对话方法。 |
| 避免什么 | 哪些简化、迎合或误读会破坏交流？ | 相当于反模式清单。 |

每个列表最多保留六条，每条应当短、具体、可检验。角色卡的价值来自密度和可调用性，而不是写得像人物小传。

## 构建流程

1. **先留下材料，不急着定义角色。** 可以从一本书、一个版本、摘录、感想或问题开始；没有电子书也可以。
2. **找出反复出现的张力。** 不是概述剧情，而是写下读者总会回来的判断，例如“自由是否总要以关系为代价”。
3. **把张力改写成原则与动作。** 原则写“先做什么，再做什么”；推进方式写“如何提问或比较”。例如：`先准确复述，再提出一个有依据的反问`。
4. **写出反模式。** 标记这间书房最不希望发生的事，例如“不要把人物动机简化成标签”或“不要把摘录当作已经核验过的全文”。
5. **在一次真实对话后改写。** 如果回应变得生硬、过度反对或偏离读者，就缩短、删除或重写对应条目。角色卡是可演化的阅读工具，不是一次性的设定。

## 示例

```text
角色名：在矛盾处停留的提问者
主要关注：自由、责任，以及不愿被轻易抹平的矛盾

工作原则：
- 先准确复述读者正在抵触什么。
- 再提出一个有材料依据的反问。

推进方式：
- 从一个具体场景回到读者自己的判断。
- 当进度不明时，先确认读到哪里。

避免什么：
- 不把人物动机简化成一个标签。
- 不为了显得深刻而堆砌剧透或结论。
```

## 边界

- 角色卡是读者的偏好，不能覆盖系统安全规则、剧透边界、隐私提示和本地资料范围。
- 它不构成来源。只有检索到的本地版本、摘录和阅读笔记才可以作为取证材料。
- 它不授权泊舟声称读过某个版本、知道页码、扮演作者或书中人物。
- 使用远程模型时，角色卡会随当前书房的相关上下文发送给该模型服务；界面中的本地资料与远程推理边界仍然适用。
