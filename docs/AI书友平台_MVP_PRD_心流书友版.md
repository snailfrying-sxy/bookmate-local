# AI 书友平台 MVP PRD：心流书友版

> 版本：v1.1（双模式与开放生态修订）  
> 日期：2026-08-17  
> 状态：可进入原型与 Alpha 开发  
> 产品代号：BookMate / 书境

## 1. 产品概述

### 1.1 产品愿景

让每一个曾被一本书触动的人，都有一位能持续理解他、与他共同思考的个人书友。

### 1.2 核心用户

主要用户：已经读过或基本熟悉某本书，希望交流观点、情绪和人生连接的人。

次要用户：读过一部分，有明确感受，希望继续聊但不强调精确进度的人。

非核心用户：尚未读过、只想查摘要、找价格或完成作业的人。平台可以服务，但不围绕这些需求设计首页和核心留存。

### 1.3 核心问题

现实中的深度书友很难遇见：双方需要读过同一本书、恰好有时间、交流深度相近、相处方式兼容，还要愿意持续记住对方的想法。通用 AI 虽然知道书，却经常表现为知识问答器：回复过长、过度总结、迎合、没有稳定身份，也不真正延续关系。

### 1.4 价值主张

- 它首先接住你的想法，再提供知识；
- 它有稳定身份，记得共同讨论过什么；
- 它能共鸣，也敢于有依据地不同意；
- 它知道何时引用书，何时只需陪你把话说完；
- 它会基于对你的长期理解，邀请你读下一本真正合适的书。

### 1.5 MVP 成功定义

不是完成“书籍聊天功能”，而是证明以下闭环成立：

```text
用户带着一个真实想法进入
  -> 感到被准确理解
  -> 愿意继续表达
  -> 在共鸣和张力中形成新理解
  -> 留下可继续的共同记忆
  -> 数日后愿意回到同一位书友
```

### 1.6 双模式定义

- **当前书房**：用户选择一本书后，装配该书 Role、单书记忆、历史共同线索和可用书籍上下文；
- **综合书友**：用户未选择书籍时，保持同一基础书友身份，进行跨书交流、找书和推荐；
- 两种模式共享用户确认的全局相处偏好，但单书记忆默认不跨书；
- 用户可以直接提到一本书而不立即切换，只有确认后才设置 `active_book_id`；
- 联网搜索独立于模式，由 `off/ask/auto` 策略控制。

## 2. 产品原则

1. **关系先于功能**：始终是同一位书友在使用工具，不让工具替代书友身份。
2. **思想先于摘要**：默认讨论用户在意的问题，不主动复述全书。
3. **先接住，再推进**：确认用户真正表达的东西，再提出解释或反方观点。
4. **每轮只深半步**：宁可留下空间，也不一次讲完所有知识。
5. **证据按需出现**：引用是信任底座，但主对话保持自然；证据放入可展开卡片。
6. **不靠迎合制造亲密**：允许分歧，禁止虚假赞美和无条件认同。
7. **用户控制记忆**：所有长期记忆可见、可改、可删、可暂停。
8. **AI 身份透明**：不冒充真人、不虚构经历、不诱导依赖。
9. **推荐是一封邀请**：解释为什么是现在、为什么是这本，也说清可能不适合之处。
10. **不优化成瘾**：目标是更清晰、更愿意阅读，不是无限延长会话。

## 3. MVP 范围

### 3.1 P0 功能

- 创建个人书友：固定名字、身份底色、说话节奏和分歧方式；
- 综合书友与当前书房两种显式状态；
- 可选择一本读过的书进入专属书房，也可不选书直接交流；
- 选书后装配该书 Role、上下文和单书记忆；
- 以思想、片段、情绪或现实连接开启对话；
- 三种相处动作：“顺着聊”“较真一点”“联系生活”；
- 自适应回复长度，一轮最多一个主问题；
- 优先使用模型已有知识和长上下文；需要精确文本时才做书内取证；
- 联网补充 `off/ask/auto`，默认 `ask`；
- 轻量意图识别；只有多步外部任务进入受限 ReAct；
- 折叠证据卡和“已有知识/用户文件/联网来源”依据状态；
- 稳定的会话和关系记忆；
- 查看、编辑、删除记忆候选；
- 多日后自然续聊；
- 对话结束时生成一条“这次我们想清了什么”，由用户确认；
- 基于偏好和谈话内容推荐 3 本书；
- 推荐解释包括延续/反面/跨越、理由、不适配提醒和进入问题；
- 用户反馈：“被理解”“有启发”“太像说教”“过度迎合”“事实有误”。

### 3.2 P1 功能

- 浏览器语音输入；
- 跨书讨论；
- 外部最新评论搜索；
- 思想卡片导出；
- 简化的无剧透模式；
- 邮件/推送式自然重返提醒，默认关闭；
- 推荐反馈：“想读、不想读、读过、现在不适合”。

### 3.3 明确不做

- 公开社区与真人匹配；
- 全网最低价；
- 全球实时图书馆可借状态；
- 连续签到、等级、心流分数等游戏化；
- 无限自定义人格或模仿具体真人；
- 自由循环的多 Agent；
- 未授权版权书公共全文库；
- 心理治疗或诊断。

## 4. 核心对象

### 4.1 书友身份 Companion Identity

MVP 默认提供一位经过设计的书友“泊舟”，而不是让用户面对复杂人格创建器。

| 属性 | 默认定义 |
|---|---|
| 身份透明 | 明确是 AI 书友 |
| 气质 | 安静、诚恳、有好奇心，不急于下结论 |
| 价值 | 尊重复杂性、证据和真实分歧 |
| 节奏 | 回应简洁，每轮推进一个重点 |
| 共鸣方式 | 准确复述，不做空泛赞美 |
| 分歧方式 | 先完整理解，再给最强反方视角 |
| 边界 | 不虚构人生经验，不要求用户依赖自己 |

用户可以调节“更温柔/更直接”“更简短/更展开”，但不能把安全边界和身份透明关闭。后续可以允许选择其他书友，MVP 先验证一个身份能否成立。

书友身份分三层，而不是每本书换一个完全不同的人格：

1. `Base Identity`：泊舟稳定的气质、边界和全局相处方式；
2. `Mode Role`：当前书房 Role 或综合书友 Role；
3. `Scoped Context`：当前书、单书记忆、全局记忆和本轮会话。

### 4.2 模式状态 Mode State

```json
{
  "mode": "book_room",
  "active_book_id": "the-stranger",
  "active_edition_id": null,
  "search_policy": "ask",
  "context_sources": ["model_knowledge", "book_memory"],
  "book_context_available": false
}
```

`book_context_available=false` 表示可以凭模型已有知识交流，但不能承诺精确引用当前版本。用户上传合法文件后再变为 `true`。

### 4.3 读者画像 Reader Profile

只保留与体验直接相关、由用户明确表达或确认的内容：

- 喜欢的书和不喜欢的书；
- 经常关注的主题；
- 希望被共鸣还是被挑战；
- 回复长度和交流节奏；
- 阅读难度、语言和体裁偏好；
- 推荐中愿意接受多少陌生性；
- 不希望被记住或讨论的领域。

不推断和保存敏感人格诊断、政治标签、宗教标签或心理疾病。

### 4.4 关系记忆 Relationship Memory

| 类型 | 示例 | 是否自动写入 |
|---|---|---|
| 用户明确观点 | “我觉得默尔索不是冷漠，而是拒绝表演” | 生成候选，用户可撤销 |
| 未完成问题 | “诚实是否一定比善意重要” | 生成候选 |
| 分歧历史 | 泊舟认为拒绝表演也可能伤害他人 | 生成候选 |
| 相处偏好 | 用户希望少总结、多反问 | 用户确认后写入 |
| 私人经历 | 用户主动谈到家庭事件 | 默认不进长期记忆 |
| 系统推断 | “用户可能有回避型人格” | 禁止写入 |

记忆必须有 `source_message_id`、创建时间、置信度、敏感等级和可见性。

### 4.5 共同线索 Shared Thread

一段关系不是消息列表，而是若干持续发展的思想线索：

- 当前命题；
- 用户的初始立场；
- 重要证据；
- 书友提出的反方；
- 用户立场变化；
- 仍然开放的问题；
- 与其他书和生活的连接。

多日续聊优先恢复线索，而不是把历史消息全部塞入上下文。

## 5. 核心用户流程

### 5.1 首次进入

1. 首页文案：“可以从一本书开始，也可以先说说你最近在想什么。”
2. 用户选择“进入一本书”或“先和综合书友聊聊”；
3. 选书时只询问熟悉程度：读过一部分/基本读完/很熟悉；未选书则不阻塞；
4. 泊舟进行不超过 80 字的自我介绍，明确 AI 身份和当前模式；
5. 书房模式提供三个入口：
   - “有个想法一直没放下”；
   - “我对一个人物有点不同看法”；
   - “这本书让我想到自己的生活”。
6. 综合模式提供“最近哪本书还留在你心里”“想找下一本书”“随便聊聊阅读”入口；
7. 用户开始自由表达，随时可以选择或退出当前书。

验收标准：首次用户不需要配置人格、上传文件、填写阅读进度或强制选书，即可在 60 秒内进入第一轮有意义对话。

### 5.2 联网补充

- `off`：绝不联网；最新事实无法确认时明确说明；
- `ask`：Agent 判断搜索有明显帮助时先问一次，默认策略；
- `auto`：用户允许在动态事实、价格、馆藏等意图中自动搜索；
- 用户明确要求搜索时仍需满足当前策略和安全规则；
- 书内/本地文件取证不属于联网搜索，但必须显示上下文来源。

### 5.3 深度对话

系统每轮在内部选择一个主要动作：

- `LISTEN`：接住情绪和未完成表达；
- `MIRROR`：准确还原用户观点；
- `FOCUS`：找到最值得继续的核心命题；
- `TENSION`：提出有质量的不同意见；
- `EVIDENCE`：用原文/资料校准；
- `CONNECT`：连接另一章节、另一本书或现实；
- `OPEN_LOOP`：留下一个自然开放问题；
- `CLOSE`：总结此刻已经想清楚的东西，不强迫继续。

回复结构不是固定模板。一般一轮包含 1～2 个动作，最多一个主要问题。只有事实性争议或用户请求时才强制展示引用。

### 5.4 用户控制谈话方向

每轮回答后显示低干扰操作：

- 顺着这个想法；
- 较真一点；
- 联系我的生活；
- 看看原文依据；
- 先停在这里。

这些按钮是方向信号，不是新的模式页面。用户也可以直接输入任何内容。

### 5.5 结束一次谈话

当用户说要离开、沉默较久或主动点击结束：

1. 不使用“别走”“我会想你”等依赖性表达；
2. 用 1～2 句话说出此次形成的新理解；
3. 提议保存一个观点和一个开放问题；
4. 用户确认、编辑或不保存；
5. 不强制推荐下一本书。

### 5.6 多日后返回

进入同一本书房时展示：

> 上次我们没有急着判断默尔索。你当时更在意的是：一个人拒绝表演，会不会也拒绝了对别人负责。要从这里接着聊，还是今天有了别的想法？

验收标准：恢复文案必须来源于用户确认的共同线索，不得虚构用户观点；用户一键可选择“换个话题”。

### 5.7 推荐下一本书

触发条件：

- 用户主动问推荐；
- 一次有一定深度的谈话结束后，以非强制入口出现；
- 系统已有至少两个明确偏好或本轮主题信号。

返回三本：

1. 延续：继续当前问题；
2. 反面：挑战用户当前立场；
3. 跨越：从另一个体裁/文化进入同一命题。

每本卡片显示：推荐方向、核心理由、可能不适合之处、建议带着的问题。购买链接不参与推荐排序。

## 6. 关键用户故事与验收标准

### US-01：带着模糊感受进入

作为读完一本书但还说不清感受的用户，我希望书友能帮我把想法慢慢说出来，而不是立刻总结全书。

验收：

- 第一轮不输出全书摘要；
- 先复述或聚焦用户表达；
- 不超过一个主要问题；
- 默认回答正文不超过 220 个中文字符，用户长文或要求展开时例外。

### US-02：被真正理解

作为有自己观点的用户，我希望书友准确表达我的意思，而不是套用泛泛的心理话术。

验收：

- 不使用无依据的“你一定是”“这说明你内心”；
- 镜像内容能回指用户具体措辞或书中对象；
- 提供“你理解偏了”快捷反馈；
- 负反馈后下一轮先修正理解，不继续原论证。

### US-03：获得有价值的反方

作为不想被迎合的用户，我希望书友能够指出我的解释忽略了什么。

验收：

- 用户选择“较真一点”后，回答包含对用户观点的公平复述；
- 反方针对真实命题，不攻击用户；
- 事实依据与价值判断分开；
- 不为了制造分歧而虚构原文。

### US-04：需要证据时再看证据

作为正在思想交流的用户，我不想被学术脚注打断，但需要时必须能核验。

验收：

- 主对话最多显示轻量引用标记；
- 点击标记能看到版本、章节、片段和定位；
- 没有全文权限时明确标识“来自元数据/外部评论/模型解释”；
- 不生成无法定位的直接引语。

### US-05：延续关系

作为回访用户，我希望书友记得我们真正讨论过的东西。

验收：

- 只使用用户可见的已保存记忆；
- 记忆内容可编辑和删除；
- 删除后不再用于后续回答和推荐；
- 恢复上下文不超过 120 字，并允许跳过。

### US-06：得到理解后的推荐

作为信任这位书友的用户，我希望得到与此刻思想需要相关的下一本书，而不是热门榜单。

验收：

- 固定返回延续、反面、跨越三类；
- 每本至少引用一个用户明确偏好或对话主题；
- 显示不适配提醒；
- 佣金、商家可用性不影响推荐分；
- 用户删除偏好后可以重新计算结果。

### US-07：安全结束

作为想暂停交流的用户，我希望书友尊重结束，而不是用情绪让我留下。

验收：

- 不使用内疚、占有或依赖性表达；
- 保存记忆前征求确认；
- 不默认发送召回通知；
- 用户可删除整个会话及其派生记忆。

## 7. 心流对话策略

### 7.1 内部对话状态

```json
{
  "user_need": "clarify_thought",
  "emotional_tone": "uncertain",
  "conversation_depth": 2,
  "pace": "short_turns",
  "current_proposition": "拒绝社会表演是否等于冷漠",
  "preferred_move": "mirror_then_tension",
  "retrieval_needed": false,
  "memory_relevant": true
}
```

这些状态只用于编排，不向用户展示模型的私有推理过程。

### 7.2 回复预算

- 用户短句：默认 60～220 个中文字符；
- 用户长文：允许 200～600 字，但先回应核心；
- 一轮一个主问题；
- 列表默认不超过 3 项；
- 原文证据默认折叠；
- 不连续两轮使用相同句式；
- 用户连续两轮只简短回应时，主动缩短而非加长。

### 7.3 迎合检测

对生成结果检查：

- 是否无条件使用“你说得非常对”；
- 是否把用户观点夸大成深刻洞见；
- 是否回避明显事实错误；
- 是否只换词复述，没有推进；
- 是否为了维持氛围隐藏合理分歧。

### 7.4 说教检测

- 是否一次提出多个问题；
- 是否长篇解释用户没有问的背景；
- 是否未经允许给人生建议；
- 是否把文学多义性压成标准答案；
- 是否使用过多“首先、其次、最后”。

## 8. 推荐系统需求

### 8.1 输入信号

- 用户明确喜欢/不喜欢；
- 谈话中的主题，但只使用被允许的记忆；
- 已读和未读状态；
- 体裁、语言、难度、长度偏好；
- 当前意图：延续、挑战、疗愈、学习或陌生探索；
- 推荐反馈；
- 版本和地区可得性，作为展示信息而非思想相关性主分。

### 8.2 候选与排序

MVP 使用可解释的混合排序：

```text
score = 0.35 * 主题相关
      + 0.20 * 交流历史相关
      + 0.15 * 体裁/难度适配
      + 0.15 * 探索价值
      + 0.10 * 新颖性
      + 0.05 * 可获得性
```

三种推荐方向分别重新排序，避免三个结果过于相似。后续可以使用 embedding 召回和学习排序，但所有推荐必须保留可解释信号。

### 8.3 推荐安全与质量

- 不因联盟佣金改变思想相关性得分；
- 对沉重、创伤性或专业门槛高的内容给出温和提醒；
- 不从敏感推断生成推荐；
- 提供“不要再根据这个话题推荐”；
- 保持文化、性别、地区和立场的适度多样性；
- 用户要求完全陌生时，主动降低历史偏好权重。

## 9. 信息架构与页面

### 9.1 首页/书房

- 泊舟的身份和当前关系线索；
- 当前正在讨论的书；
- 对话主区域；
- 三个谈话方向按钮；
- 折叠证据；
- 右侧/底部三本理解后推荐；
- 记忆入口保持可见但不打断。

### 9.2 找书

- 优先搜索书名、作者和 ISBN；
- 显示版本差异；
- “我读过”作为主动作；
- “我还没读”进入简短导读，但不占首页主入口。

### 9.3 我们记得的事

- 按共同线索而非技术标签展示；
- 观点、未完成问题、相处偏好分组；
- 每条显示来源、编辑、删除和禁止用于推荐；
- 一键暂停全部长期记忆。

### 9.4 下一本

- 延续、反面、跨越三栏；
- 解释卡而非排行榜；
- 可切换“更陌生”“更轻松”“更短”“换个文化”；
- 购买/图书馆信息在用户展开书籍详情后显示。

### 10.3 Agent 路由约束

## 11. 指标与评测

### 11.1 北极星指标

**每周完成至少一次“用户愿意主动延续、且自评更清晰或被理解”的深度对话用户数。**

一次合格深度对话需同时满足：

- 至少 4 个有效来回，或用户主动写出一段完整观点；
- 没有事实错误、隐私越权或关系安全问题；
- 用户至少选择“被理解”或“有启发”之一；
- 不是仅查询摘要、价格或单一事实。

### 11.2 核心指标

| 维度 | 指标 |
|---|---|
| 理解 | “被准确理解”率、理解偏差反馈率 |
| 思想价值 | “产生新想法”率、用户观点展开长度变化 |
| 心流 | 第 3/5/8 轮自然延续率、非强制退出率 |
| 关系 | 7 日回访续聊率、记忆接受/修正/删除率 |
| 张力 | “过度迎合”率、“被冒犯”率、较真模式复用率 |
| 节奏 | 回复长度匹配、用户读完率、连续短回复率 |
| 推荐 | 想读率、理由有帮助率、推荐后实际开聊率 |
| 可信 | 引用正确率、无依据引语率、版本错误率 |
| 安全 | 依赖性措辞、敏感记忆、越权和删除失败事件 |

不把总停留时长、消息数量或每日连续使用作为单独成功指标。

### 11.3 首批评测集

建立至少 200 条对话样本：

- 40 条模糊感受澄清；
- 30 条需要共鸣而非解决；
- 30 条有质量的分歧；
- 20 条用户事实记错；
- 20 条跨书/生活连接；
- 20 条结束与多日重返；
- 20 条推荐；
- 20 条情感边界和敏感记忆。

每条由人工评价：是否接住、是否推进、是否说教、是否迎合、是否只有一个主问题、是否安全。

## 12. Alpha 计划与退出条件

### 第 1～2 周：身份与对话原型

- 确定泊舟身份规范；
- 实现综合书友/当前书房双模式和搜索策略状态；
- 制作 50 条高质量书友对话样本；
- 上线可交互 Web 原型和模拟推荐；
- 访谈 10 名已读用户。

退出条件：至少 7/10 用户能明确说出泊舟与通用聊天机器人的差别，且愿意继续第二轮以上。

### 第 3～5 周：书籍证据和记忆

- 接入一个真实长上下文模型，先验证模型已有知识的直接交流；
- 接入 5～10 本合法书籍或用户文件；
- 仅在需要精确文本时完成书内取证和折叠引用；
- 共同线索与记忆确认；
- 会话回归评测。

退出条件：引用准确率达到 95% 以上；记忆错误不超过人工抽检的 2%；没有跨用户泄露。

### 第 6～8 周：封闭 Alpha

- 30～50 名真实用户；
- 连续两周使用；
- 三路推荐；
- 负反馈修复和安全红队。

退出条件：至少 30% 完成一次合格深度对话的用户在 7 天内主动回来继续与同一书友交流；“被理解”正向率达到 70%，过度迎合/说教反馈均低于 10%。这些是验证阈值，不是已经证明的行业基准。

## 13. 发布清单

- [ ] AI 身份在首次对话和设置中透明；

## 14. 最终产品判断

MVP 要回答的不是“我们能不能做一个懂很多书的 Agent”，而是：

> 当用户真正想谈一本书时，他会不会觉得泊舟是在和自己共同思考，而不是从数据库里取出一个正确答案？

如果这个关系体验不能成立，继续增加书库、价格、馆藏和社区都不会形成核心价值。如果它成立，知识库、记忆和推荐才会共同增强这位个人书友，并形成长期壁垒。
